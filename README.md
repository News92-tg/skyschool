# SkyySchool

Учебная платформа: подготовка к ЕГЭ и ОГЭ, шахматы с собственным
движком, развивающие игры для младших, режим дня и AI-учителя с разными
манерами объяснять.

Статический сайт: ни сборки, ни зависимостей, ни сервера. Кладётся в
репозиторий и открывается по адресу GitHub Pages.

Есть две сборки одного и того же сайта:

* **обычная** — отдельные страницы, как ниже. Для GitHub Pages.
* **`single.html`** — весь сайт одним файлом, разделы переключаются
  по адресу вида `#trainer`. Удобно, когда нужно открыть платформу
  одной ссылкой или показать её без хостинга. Собирается командой
  `python3 bundle.py` из корня проекта.

## Быстрый старт

```bash
git clone https://github.com/news92-tg/skyschool.git
cd skyschool
python -m http.server 8080
```

Открыть `http://127.0.0.1:8080`.

Двойным щелчком по `index.html` сайт не заработает: браузер не даёт
странице с `file://` подгружать соседние скрипты. Нужен любой локальный
сервер — команда выше подойдёт.

Публикация: **Settings → Pages → Deploy from branch → main → / (root)**.
Через минуту сайт будет на `https://news92-tg.github.io/skyschool/`.

## Два режима работы

Сайт работает сразу после клонирования, без всякой настройки — но в
двух разных режимах, и разницу важно понимать.

**Локальный режим** (пока ключи Supabase не заполнены). Всё хранится в
`localStorage` браузера: прогресс, профили, домашние задания, переписка.
Можно завести учителя и ученика, выдать задание, решить его, обменяться
сообщениями — но всё это в пределах одного устройства. Учитель со своего
компьютера ученика не увидит. Для знакомства с платформой и для показа
этого достаточно.

**Сетевой режим** (ключи заполнены). Настоящие аккаунты, данные общие:
учитель задаёт домашнее задание у себя, ученик открывает его дома на
телефоне. Живая партия в шахматы идёт между разными устройствами.

Переключение — только заполнение двух полей. Переписывать ничего не
нужно: страницы про режим не знают, за это отвечает `assets/db.js`.

## Подключение Supabase

1. Создайте проект на supabase.com (бесплатного тарифа хватает).
2. **SQL Editor → New query** → выполните по очереди три файла:
   `sql/schema.sql`, затем `sql/schema-classes.sql`, затем
   `sql/schema-ai-teachers.sql`. Первый создаёт таблицы, правила
   доступа и триггер, который заводит профиль при регистрации;
   остальные два описаны ниже. Все три можно запускать повторно —
   дублей не создадут.
3. **Project Settings → API** — скопируйте `Project URL` и ключ `anon`.
4. Впишите их в `assets/config.js`:

```js
SUPABASE_URL: 'https://xxxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJhbGci...',
```

**Про ключ anon.** Он публичный по замыслу и лежит в коде любого сайта
на Supabase — прятать его не нужно и невозможно. Данные защищает не он,
а правила RLS из `schema.sql`: они выполняются на сервере и решают, кому
какие строки показывать. Поэтому схему обязательно нужно применить —
без включённого RLS база действительно будет открыта всем.

А вот ключ `service_role` — полная противоположность: он даёт полный
доступ в обход всех правил. В файлы сайта он попадать не должен никогда.

### Классы, роли, онлайн-тетрадь (sql/schema-classes.sql)

Вторая миграция, поверх `schema.sql`. Добавляет то, чего в базе не
хватало для работы с классами и для будущих разделов (фото-проверка
домашки, совместная тетрадь):

`classes` и `class_members` — классы с кодом приглашения на 6 символов
(без букв I, O и цифр 1, 0 — их путают, когда код диктуют вслух).
Вступление идёт через функцию `join_class(code)`, а не прямым запросом:
ученик не может прочитать класс, в котором ещё не состоит, — RLS не
даст, — поэтому функция проверяет код сама и добавляет только того,
кто её вызвал.

`family_links` — связь «родитель ↔ ребёнок». В `schema.sql` роль
`parent` в списке ролей была, а связи не было, то есть роль ничего не
давала. Привязку подтверждает ребёнок, а не родитель: иначе кто угодно
объявил бы себя родителем чужого ученика и получил доступ к его
оценкам.

`task_attempts` — попытки решения. Раньше прогресс тренажёра жил
только в `localStorage`, и учитель его не видел. Теперь есть функция
`weak_topics(ученик)` — доля ошибок по темам, то самое «у него плохо с
процентами». У таблицы намеренно нет политик `update` и `delete`:
переписать историю своих ошибок нельзя, иначе статистика превращается
в самоотчёт.

`notebook_sessions` — состояние совместной тетради одним `jsonb`,
добавлена в публикацию `supabase_realtime` (без этого доска у второй
стороны не обновляется сама).

`photo_checks` — результат разбора фото тетради: распознанный текст,
оценка, ошибки, отзыв. Отдельная таблица, а не поля в `homework`:
`homework` — это «задание, которое учитель выдал», а разбор — «работа,
которую ученик сдал». В одной таблице половина колонок всегда была бы
пустой. Плюс триггер-ограничитель: не чаще одного разбора в 30 секунд
на пользователя, проверка стоит в базе — клиентскую обходят открытием
консоли браузера.

### Проверка правил доступа

RLS — это не комментарий в схеме, а то, от чего зависит, увидит ли
один ученик домашку другого. Поэтому правила проверяются тестами:

```bash
bash scripts/test-rls.sh
```

Скрипт поднимает временный PostgreSQL, кладёт в него заглушку Supabase
(`sql/tests/00-supabase-stub.sql` — локальная подмена `auth.users` и
`auth.uid()`), применяет все три миграции и прогоняет `sql/tests/rls-tests.sql`:
55 проверок — посторонний ученик не видит чужих ДЗ, сообщений, попыток,
фото, тетрадей и шахматных партий; чужой учитель не видит ученика, которого не ведёт;
родитель видит своего ребёнка, но не может править ему оценку; админ
видит всё; подделать запись от чужого имени нельзя; код приглашения
работает, неверный — нет. Скрипт падает с ненулевым кодом, если хоть
одна проверка не прошла.

Проверяется и то, что чужой приватный AI-учитель не виден, что нельзя
переписать промпт встроенного учителя (он раздаётся всем ученикам сразу,
это самое опасное из возможного), что второй отзыв на того же учителя не
принимается и что средний рейтинг пересчитывает триггер.

Текущий результат: **55 из 55 пройдено** на PostgreSQL 16.

Если у вас стоит Supabase CLI, то же самое можно прогнать на настоящем
локальном Supabase — `supabase start`, затем применить `sql/schema.sql`
и `sql/schema-classes.sql` и выполнить `sql/tests/rls-tests.sql` (файл
заглушки в этом случае НЕ нужен: всё, что он подменяет, там уже есть).

### Демоданные (необязательно)

`sql/seed.sql` заполняет свежую базу примером: один учитель, один
ученик, связь между ними, одно домашнее задание и одна шахматная
задача — чтобы сайт не выглядел пустым при первом показе.

Автоматически создать «фейковых» учителя и ученика нельзя: таблица
`profiles` привязана внешним ключом к `auth.users`, а строки в
`auth.users` — с захешированным паролем и служебными записями —
создаёт только сама система входа Supabase, не прямой INSERT. Поэтому
порядок такой:

1. Зарегистрируйтесь на сайте как учитель и как ученик (два разных
   email — например `teacher.demo@…` и `student.demo@…`, свои
   значения впишите в начало `seed.sql`).
2. Supabase → SQL Editor → вставьте `seed.sql` → Run. Скрипт идемпотентен —
   повторный запуск дублей не создаст.

## Разбор от ИИ

Подключается двумя способами, и они решают разные задачи.

**Способ 1: свой ключ через интерфейс.** На странице тренажёра есть
кнопка «Подключить разбор от ИИ» — вводите туда ключ DeepSeek. Он
сохраняется в localStorage вашего браузера и никуда больше не
попадает: ни в файлы сайта, ни в репозиторий, ни к другим посетителям.
Тратится ваш баланс. Подходит, когда платформой пользуетесь вы сами.

Оговорка: запрос уходит из браузера прямо в DeepSeek, а некоторые API
такие запросы со страниц не принимают. Если разбор не открывается —
страница скажет об этом прямо, и тогда нужен способ 2.

**Способ 2: Worker.** Ключ живёт на сервере, посетителям не виден,
разбор работает у всех. Единственный правильный вариант для публичного
сайта: иначе либо каждый вводит свой ключ, либо ключ утекает.

**Ключ DeepSeek нельзя вписывать в `config.js` ни при каком способе.**
GitHub Pages отдаёт файлы как есть: ключ увидит любой, кто откроет
исходник страницы. По GitHub круглосуточно ходят боты, которые ищут
строки вида `sk-…`, и найденный ключ тратят за часы.
В `AI_BASE` идёт **адрес Worker**, а не ключ:

```js
AI_BASE: 'https://skyschool-ai.ваш-логин.workers.dev',   // правильно
AI_BASE: 'sk-0329ade0...',                               // так работать не будет
```

Разворачивается за пять минут, бесплатно, карта не нужна:

```bash
cd worker
npx wrangler login
npx wrangler secret put DEEPSEEK_API_KEY   # вставить НОВЫЙ ключ
npx wrangler secret put GEMINI_API_KEY     # нужен только для домашки по фото
npx wrangler deploy
```

Полученный адрес открывается в браузере: если видите
`{"ok":true,"hasKey":true,"hasVision":true}` — Worker жив и оба ключа
на месте. Впишите этот адрес в `AI_BASE`. Там же в ответе видны
действующие лимиты — удобно проверить, что настройки применились.

**Четыре эндпоинта:** `/explain` — разбор задания, `/check-photo` —
домашка по фото с оценкой 1–5 голосом ИИ-учителя (Gemini Vision →
DeepSeek), `/photo-analyze` — фотография условия: распознать и решить
по шагам (только Gemini, код в `worker/photo-analyze.js`),
`/chess-explain` — объяснение уже посчитанной оценки хода.

Два фото-эндпоинта делают разную работу: первый отвечает на «проверь
мою работу», второй — на «объясни это задание». Счётчик частоты у них
общий: дорого именно распознавание, и чередование маршрутов не должно
удваивать разрешённое. `/photo-analyze` работает и без ключа DeepSeek —
ему достаточно `GEMINI_API_KEY`.

Снимки лежат в закрытом бакете Supabase `homework`, доступ — по
временным ссылкам на час; политики в `sql/schema-storage.sql`
разрешают ученику только его собственную папку, а учителю — папки его
учеников. Публичный бакет здесь не годится: на фото детская тетрадь с
именем на обложке, а адрес файла подбирается легче, чем кажется.

**Лимиты и модели не зашиты в код.** Числа в тарифах и названия
моделей меняются часто, и менять их правкой кода с последующей выкаткой
неудобно. Всё перечисленное — переменные окружения со значениями по
умолчанию, правятся в панели Cloudflare или в `worker/wrangler.toml`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `RATE_PER_MIN` | 20 | запросов с одного адреса в минуту |
| `RATE_PHOTO_SECONDS` | 30 | пауза между разборами фото |
| `RATE_CHESS_SECONDS` | 3 | пауза между объяснениями ходов |
| `MAX_IMAGE_KB` | 1200 | потолок размера фото после сжатия |
| `DEEPSEEK_MODEL` | deepseek-chat | модель для текста |
| `GEMINI_MODEL` | gemini-2.5-flash | модель для распознавания |
| `MAX_TOKENS` / `MAX_TOKENS_PHOTO` | 500 / 900 | потолок ответа |
| `ALLOWED_ORIGINS` | список в коде | домены, которым можно обращаться |

Частота для фото считается отдельно от общего счётчика намеренно:
двадцать распознаваний подряд стоят совсем других денег, чем двадцать
текстовых разборов.

В `worker/worker.js` уже сделаны белый список источников, ограничение
частоты и обрезка входных данных, чтобы чужой сайт не смог тратить ваш
баланс. Свой домен добавьте в массив `ALLOWED`.

Если разбор не работает, страница скажет что именно сломалось: пустой
`AI_BASE`, не адрес вместо адреса, Worker не отвечает или DeepSeek
вернул ошибку с её кодом.

## Что внутри

### Оффлайн-режим (PWA)

Сайт — прогрессивное веб-приложение: `manifest.json` + `sw.js` (service
worker). После первого открытия страницы, банки заданий, шрифты и
стили кэшируются, и сайт можно открывать без интернета — тренажёр,
шахматы, калькулятор и уже скачанная песочница Python работают офлайн.
Живые вещи (вход, синхронизация с Supabase, разбор от ИИ) из кэша
намеренно исключены: без сети они честно недоступны, а не отдают
устаревшие данные. Первое открытие каждой страницы всё равно требует
интернета — офлайн работает только то, что уже когда-то загружалось в
этом браузере. На телефоне сайт можно «установить» через «Добавить на
экран «Домой»» — тогда он откроется как обычное приложение.

### Тренажёр

**1428 заданий** по тринадцати предметам: математика, информатика,
русский язык, физика, биология, химия, география, обществознание,
история, английский, польский, испанский, немецкий. Каждое с
подсказкой и полным разбором — не «правильный ответ B», а почему
получается именно так и на чём здесь обычно ошибаются.

Честно про объём: цель была «более 3000», по факту получилось 1428
(плюс 18 в детском разделе). Это больше похоже на полноценный учебный
год, чем на неделю, но не на три тысячи — писать разборы, которые
реально объясняют, а не подставляют случайный текст, быстрее не
получилось. Нарастить банк проще всего: см. «Как добавить задание».

Русский, география, обществознание и история — только на русском
(`ruOnly: true`): переводить, например, вопрос про «Смутное время», а
не про грамматику, смысла нет — на английском интерфейс честно
говорит, что раздел доступен только по-русски, а не показывает
необъяснённый русский текст. Английский, польский, испанский и
немецкий — языковые банки: базовая грамматика, лексика и перевод;
польский/испанский/немецкий — на уровне A1–A2 (основы), английский —
подробнее (100 заданий, уровень подготовки к ЕГЭ/ОГЭ по английскому).

Порядок вариантов перемешивается при показе. В файлах базы верный ответ
стоит первым (так их удобно писать и проверять), но показывать в том же
порядке нельзя — иначе можно жать «A», не читая условие.

### Инструменты

Раздел `tools.html` (в меню — «Инструменты»): три вкладки.

* **Калькулятор** — обычный и инженерный, с историей вычислений.
* **Справочный браузер** — окно с адресной строкой и подборкой ссылок
  на справочные сайты. Честная оговорка: многие сайты запрещают
  показывать себя во встроенном окне (`X-Frame-Options`) — тогда
  страница прямо об этом говорит и даёт открыть ссылку в новой вкладке,
  а не притворяется, что всё работает.
* **Python** — песочница на Pyodide (Python, скомпилированный в
  WebAssembly, выполняется прямо в браузере). Первый запуск скачивает
  среду выполнения (~10–15 МБ) и требует интернет; дальше, в этом же
  браузере, работает офлайн вместе с остальным сайтом.

### Python прямо в задании (тренажёр → информатика)

Отдельно от «Инструментов» — `assets/python-editor.js`: тот же Pyodide,
но встроенный прямо в карточку задания тренажёра. Показывается только
когда одновременно верно: предмет — информатика, И у задания стоит
`needsCode: true`. Сейчас в базе таких заданий нет (механизм есть,
включается одним полем в `data/bank-informatics.js`) — редактор не
покажется ни на одном текущем задании, пока такое поле кому-то не
проставят.

Версия Pyodide (0.26.4) специально совпадает с версией в «Инструментах»
— иначе браузер скачивал бы два разных рантайма вместо одного. При
первом запуске показывается всплывающее предупреждение про ~10–15 МБ и
интернет; дальше редактор в задании работает офлайн так же, как
песочница в «Инструментах» (кэшируется тем же service worker'ом —
отдельно ничего дописывать не пришлось, `sw.js` кэширует сторонние
ресурсы по origin, а не по конкретному URL).

### Проверка базы заданий

`scripts/validate-banks.py` — отдельный скрипт (только стандартная
библиотека Python, без node и внешних пакетов), который разбирает все
`data/bank-*.js` собственным маленьким парсером (учитывает кавычки и
вложенные скобки — не наивная регулярка на весь файл) и проверяет:
уникальность id внутри банка и между банками, `answer` в допустимых
границах, отсутствие одинаковых вариантов ответа в одном задании,
наличие `text.ru`/`solution.ru`, двойные пробелы и пробелы по краям.

```bash
python3 scripts/validate-banks.py          # отчёт
python3 scripts/validate-banks.py --fix    # + схлопнуть двойные пробелы
```

Текущий результат: **1428 заданий, 14 предупреждений** — и все 14
оказались ложным срабатыванием: это отступы в Python-коде и
выравнивание ASCII-таблиц внутри `bank-informatics.js` (там показывают
код или таблицу переходов автомата прямо в условии), а не опечатки.
Поэтому `--fix` на них не запускался — схлопнуть эти «пробелы» значило
бы сломать форматирование кода в условии. Все остальные банки — 0
предупреждений.

Честная оговорка: скрипт проверяет структуру, не факты. Даты, формулы,
исторические события он не сверяет — это может сделать только человек
или профильный эксперт. Точечно я это уже делал вручную (например,
поймал и переписал три плохих задания в `bank-russian.js` и опечатку в
`bank-history.js`), но сплошной фактчекинг 1428 заданий в рамках
автоматической проверки не входил.

### Интервальное повторение

Каждое задание живёт в «коробке» от 0 до 5. Ответили верно — коробка
растёт, показ откладывается: 1, 3, 7, 16, 35 дней. Ошиблись — падает в
нулевую и возвращается завтра.

Это метод Лейтнера. Он заметно лучше, чем прорешивать сборник подряд:
время уходит на то, что вы плохо помните, а не на то, что и так знаете.

### Шахматы

Ходы анимированы: фигура едет на новую клетку, съеденная сжимается и
исчезает. При взятии на проходе сжимается именно та пешка, которую
забрали, а не пустое поле, куда пошла своя. Конец партии показывается
отдельным окном: что произошло, почему, сколько было ходов и сколько
фигур каждая сторона потеряла.

Правила написаны с нуля: доска 0x88, рокировка, взятие на проходе,
превращение, мат, пат, ничья по материалу и по правилу 50 ходов,
шахматная нотация.

Движок проверен **perft-тестами** — эталонным способом проверки
шахматных программ: из известной позиции считается точное число всех
возможных партий на заданную глубину и сверяется с опубликованным.

| Kiwipete | 4 | 4 085 603 | 4 085 603 ✓ |

Совпадение на миллионах позиций означает, что правила реализованы точно,
включая случаи, которые вручную не проверить.

Бот — минимакс с альфа-бета отсечением, таблицами полей и досчётом
взятий. Четыре уровня, считает в браузере, никуда ничего не отправляет.

Все 12 задач проверены программно: маты действительно маты (и других
матующих ходов в позиции нет), тактика подтверждена перебором.

**Задания от учителя.** Учитель составляет позицию и указывает верный
ход, ученик решает на доске, движок проверяет сам. Перед отправкой
задание проверяется: читается ли позиция, есть ли на доске оба короля,
возможна ли такая позиция в партии вообще и существует ли указанный ход.

**Живая партия.** Создаёте партию, получаете короткий код, соперник
входит по нему. В сетевом режиме — с любого устройства через Supabase
Realtime. В локальном — между вкладками одного браузера: откройте сайт
во втором окне и войдите по коду.

### Детям

«Три в ряд», где ходы не даются даром: они зарабатываются решёнными
заданиями. Кончились ходы — решите задачу, получите пять новых. Плюс
игра на память и счёт на скорость.

Движок игры проверен тестами: стартовое поле никогда не содержит готовых
рядов, на поле всегда есть хотя бы один возможный ход, а если ходов не
осталось — фишки пересобираются без потери очков.

### AI-учителя

Страница «Учителя» — это выбор не человека, а манеры объяснять.
Учитель — набор из системного промпта, строгости (1–5), языков и целей;
именно его промпт уходит в DeepSeek, когда вы жмёте «разбор от ИИ».
Один и тот же разбор Сократ выстроит цепочкой вопросов, а Строгий Пётр —
перечнем того, за что на экзамене снимут балл. Выбранный учитель виден
в шапке тренажёра, меняется в любой момент, прогресс при этом не
трогается.

Шесть базовых: Сократ (философ, не даёт готовый ответ), Строгий Пётр
(экзаменатор, строгость 5), Добрый Макс (объясняет на бытовых
примерах), профессор Ломоносов (откуда взялось правило и где перестаёт
работать), коуч Аня (называет один следующий шаг), Малыш (для 5–10
лет).

Промпты написаны поведенчески — «делай вот это, не делай вот того», а
не «ты добрый». Расплывчатая роль даёт одинаковый ответ у всех шестерых,
и тогда выбор учителя становится украшением.

Где что лежит и почему именно так:

* `data/ai-teachers.js` — тексты промптов шести базовых. В файле, а не
  только в базе, потому что сайт обязан работать офлайн и без Supabase:
  иначе в локальном режиме выбирать было бы не из кого.
* `assets/ai-teachers.js` — выбор учителя (localStorage, а при
  подключённом Supabase ещё и в профиль, чтобы выбор переехал на другое
  устройство), сборка промпта, отзывы.
* `sql/schema-ai-teachers.sql` — таблица `teachers_ai` (метаданные,
  рейтинг, пользовательские учителя), `teacher_reviews` (один отзыв на
  учителя от человека, среднее считает триггер в базе — клиент видит не
  все строки и посчитал бы неверно), `chess_sessions`.
* `worker/worker.js` — свой экземпляр тех же промптов.

Последнее — осознанное дублирование, и вот почему. В режиме Worker
браузер отправляет на сервер **идентификатор** учителя, а не текст
промпта. Если принимать текст, Worker превращается в бесплатный доступ
к вашему ключу DeepSeek для любых задач — от чужих курсовых до попыток
обойти ограничения модели. Поэтому список промптов держит сам Worker.
Правя формулировку в одном месте, поправьте во втором; неизвестный
идентификатор Worker не считает ошибкой — отвечает общим промптом, так
что старый Worker продолжает работать с новым сайтом.

У встроенных шестерых `style_prompt` в базе намеренно пустой: текст
берётся из файла. Иначе было бы два источника правды, которые разойдутся
при первой же правке, и никто не заметит, какой из них работает.
Пользовательские учителя — наоборот, полностью из базы.

### Домашка по фото

Страница «Домашка по фото»: снимок страницы тетради → распознавание →
оценка и разбор ошибок от выбранного учителя. Делается в два шага и
двумя разными моделями, потому что одна модель обе задачи не решает:
картинки читает Gemini Vision, оценивает прочитанное DeepSeek с
промптом и строгостью выбранного учителя.

Что важно в устройстве:

Фото сжимается **в браузере** до 1024 px по длинной стороне, качество
подбирается под потолок размера. Снимок с телефона — это 3–6 МБ, и
гонять их целиком незачем; для чтения текста этого разрешения хватает.

**Распознанный текст показывается отдельно и всегда** — это не деталь
оформления. Распознавание детского почерка ошибается, и оценка,
выставленная по неверно прочитанному тексту, выглядит убедительно и
при этом несправедлива. Без показа исходника ученик спорит с оценкой
вслепую.

Отсюда же кнопка **«Это распознано неверно»**: она ставит
`ocr_flagged` в базе. Это единственный способ узнать, как часто модель
врёт на почерке — со стороны это не видно. Ученику при этом разрешено
менять только этот флаг: RLS сама по себе колонки не различает, поэтому
остальное сторожит триггер, иначе «пожаловаться на распознавание»
превратилось бы в «поставить себе пятёрку». Оценку правит учитель —
последнее слово за человеком, не за моделью.

**Фотографии нигде не хранятся.** В базу идут распознанный текст,
оценка и разбор; сам снимок остаётся в галерее телефона. Так проще,
дешевле и не требует настройки хранилища с отдельными правилами
доступа. Если понадобится история со снимками — это отдельный шаг
(bucket в Supabase Storage и политики к нему).

Раздел работает только через Worker: ключ Gemini нельзя держать в
браузере. Пока `AI_BASE` пуст, страница честно об этом говорит и не
притворяется рабочей.

### Разбор шахматных ходов

После каждого хода сбоку появляется оценка: отличный ход, хороший,
неточность, ошибка или грубая ошибка — с указанием, что было сильнее.

**Считает движок, а не языковая модель.** Это принципиально. Языковая
модель не умеет оценивать позицию: она выдаст уверенный ярлык,
регулярно неверный, и предложит «лучшие ходы», часть которых в данной
позиции невозможна. Ученик не сможет отличить такую подсказку от
настоящей — он для того и учится. Движок же считает точно, мгновенно,
офлайн и бесплатно. Модель подключается только последним слоем: берёт
готовый вердикт и переводит его в живую фразу от лица выбранного
учителя. Без интернета и без ИИ раздел работает, просто без словесного
пояснения.

Две вещи в расчёте, которые выглядят мелочью, но решают всё.

*Глубина «до» и «после» разная.* Позиция до хода считается на 3
полухода, позиция после — на 2. Если считать одинаково, второй расчёт
заглядывает на полуход дальше первого (ход-то уже сделан), и числа
оказываются с разных горизонтов. Ошибка при этом не случайная: на
нечётной глубине сторона, которая ходит, получает лишний темп, и
оценка скачет от полухода к полуходу. На практике это выглядело так,
что ход **1.e4 получал ярлык «ошибка»**.

*Порогов два, а не один.* Движок на малой глубине знает две разные по
надёжности вещи. Материал он считает точно: не стало фигуры — значит,
не стало. Позиционную разницу в полпешки он различает плохо, и это шум
его близорукости, а не ошибка ученика. Поэтому: потерял материал —
меряем строго; материал цел, разница только в оценке — планка втрое
выше. С общими порогами движок называл ошибкой ход 3.c3 в итальянской
партии — книжный ход, который играют двести лет. Ученик, которому
платформа говорит «ошибка» за нормальный ход, перестаёт ей верить, и
правильно делает.

Проверяется тестами:

```bash
node scripts/test-chess-review.js
```

17 проверок: зевок ферзя обязан называться зевком, отказ забрать
висящую фигуру — ошибкой, мат — не ошибкой, невозможный ход —
отказом разбора, а вся итальянская партия целиком не должна получить
ни одного «mistake». Отдельно меряется время: разбор считается на
главном потоке сразу после хода, и если он занимает секунды, интерфейс
подвисает после каждого хода. Сейчас в среднем 80 мс, в пике 190.

## Как добавить задание

Один объект в массив в нужном файле `data/bank-*.js`. Пересобирать
ничего не нужно.

```js
{
  id:'m16',                        // уникальный в пределах всей платформы
  exam:'ege',                      // 'ege' | 'oge' | 'both'
  difficulty:'medium',             // 'easy' | 'medium' | 'hard'
  topic:{ru:'Дроби', en:'Fractions'},
  text:{ru:'Условие…'},
  options:[{ru:'1/2'},{ru:'2/3'}],
  answer:0,                        // индекс верного, с нуля
  hint:{ru:'Подсказка…'},
  solution:{ru:'Разбор…'}
}
```

Английский (`text.en`/`options[].en`/`hint.en`/`solution.en`) нужен
только там, где банк не помечен `ruOnly: true` — сейчас это математика,
информатика, физика, биология, химия и четыре языковых банка
(английский, польский, испанский, немецкий — для них `text`/`options`
на самом иностранном языке, а `hint`/`solution` поясняют его отдельно
по-русски и по-английски). Русский язык, география, обществознание и
история — только по-русски: переводить задание про правописание «н» и
«нн» или про «Смутное время» смысла нет. В английском интерфейсе про
это говорится прямо, а не показывается русский текст без объяснений.

**`solution` пишется всегда**, даже когда подключён ИИ: разбор из базы
не зависит от интернета, баланса и настроения модели.

## Данные пользователя

В локальном режиме всё лежит в `localStorage` под ключами `sky_*`.
На сервер не уходит ничего, но и на другое устройство не переносится, и
пропадёт при очистке браузера. На странице «План» есть кнопка «Сделать
копию»: она показывает все данные текстом, который можно скопировать и
сохранить куда угодно. Текстом, а не файлом по ссылке, потому что
программное скачивание в части окружений молча блокируется — кнопка
нажимается, а файла нет.

В сетевом режиме прогресс тренажёра всё равно остаётся локальным, а в
Supabase уходят профили, связи, задания, сдачи, сообщения и партии.
